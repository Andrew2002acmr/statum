# AGENTS.md

## Контекст проекта

- Проект - лендинг для получения заявок на ремонтные работы.
- Главное целевое действие - отправка формы заявки.
- `design/statum-design.jpg` считать приблизительным визуальным референсом, а не точным макетом.
- Извлеченные иконки и сгенерированный текст считать неподтвержденными до отдельного согласования.
- Не придумывать контакты, отзывы, цены, гарантии, юридические данные и факты о компании. Использовать `TBD`.

## Правила документации

- Поддерживать актуальность `docs/DESIGN-AUDIT.md`, `docs/SPEC.md`, `docs/IMPLEMENTATION-PLAN.md` и `docs/OPEN-QUESTIONS.md`.
- Для значимых продуктовых, дизайн- и технических решений указывать источник: `[Макет]`, `[Материалы]`, `[Рекомендация]`, `[Предположение/TBD]` или `[Бриф]`.
- Если решение меняется во время реализации, обновлять соответствующий документ в той же задаче.

## Правила работы с кодом

- Следовать зафиксированному стеку из `docs/TECH-STACK.md`.
- Использовать Astro, TypeScript strict, Astro Components и обычный TypeScript для простой клиентской интерактивности.
- Делить интерфейс на небольшие секции и компоненты: header, hero, form, trust strip, process, services, portfolio, reviews, CTA, footer.
- Хранить фактический контент в data/config-слое, чтобы неподтвержденные значения было легко найти и заменить.
- Использовать семантический HTML и логичную иерархию заголовков.
- Не менять исходные дизайн-файлы без прямой просьбы.
- Не делать нерелевантные рефакторы.

## Правила зависимостей

- Не устанавливать и не скачивать зависимости без отдельной задачи на реализацию.
- Добавлять зависимости только если они решают конкретную задачу.
- Не добавлять React, Preact, Vue, Next.js, Express, NestJS, базы данных, Redis, Redux, UI-библиотеки или тяжелые animation/slider-библиотеки без отдельного согласования.
- Использовать один набор иконок: Lucide.
- Не смешивать извлеченные Illustrator SVG с иконками другой стилистики.
- Не поставлять в production SVG, содержащие посторонние embedded base64 PNG.

## Адаптивность и стили

- Использовать Tailwind CSS вместе с CSS custom properties для дизайн-токенов.
- Scoped CSS применять только для сложных отдельных секций.
- Сохранять темно-золотое направление макета, но проверять читаемость и контраст.
- Не использовать вложенные карточки, чрезмерные тени и декоративные градиентные пятна.
- Поддерживать мобильные экраны от 320 px.
- Не допускать горизонтального скролла и перекрытия текста.
- Пятиколоночные desktop-ряды адаптировать в читаемые mobile/tablet-layouts.

## Форма

- Форму заявки реализовывать через Astro Actions и Zod.
- Форма должна иметь labels, валидацию, consent checkbox, states `loading`/`success`/`error`, honeypot и защиту от повторной отправки.
- Канал отправки заявки - `TBD` до согласования.
- До подключения реального обработчика не показывать пользователю ложное сообщение об успешной отправке.
- Не обещать срок ответа, если клиент его не подтвердил.

## Доступность

- Все интерактивные элементы должны быть доступны с клавиатуры.
- Focus-visible состояния обязательны.
- Поля формы должны иметь настоящие label.
- Для смысловых изображений нужны alt-тексты, для декоративных - пустой alt.
- Если добавляются анимации, учитывать `prefers-reduced-motion`.

## Производительность

- Оптимизировать изображения перед production.
- Использовать responsive images и lazy loading ниже первого экрана.
- Держать JavaScript минимальным.
- Перед завершением реализации запускать production build.

## Тестирование и проверка результата

- Для задач реализации проверять минимум: build, `astro check`, ESLint, Prettier, форму, клавиатурную навигацию и отсутствие выдуманных production-данных.
- Через Playwright проверять страницу на 1440, 1024, 768 и 390 px.
- Проверять отсутствие горизонтального скролла и наложения элементов.
- Если в проекте есть lint, format или test scripts, запускать релевантные проверки перед финальным ответом.
- В финальном ответе сообщать, какие проверки выполнены, а какие не удалось запустить.

## Git и рабочее дерево

- Сохранять пользовательские изменения и не откатывать несвязанные файлы.
- Делать небольшие проверяемые коммиты, если пользователь просит коммит.
- Префикс веток по умолчанию: `codex/`.
